# 输出模板（Output Template）

## 严重度分级
| 级别 | 含义 | 处理 |
|---|---|---|
| P0 | 事实错误 / 会误导，立即修正 | 必须补 |
| P1 | 关键场景缺失或深度不足，实战会卡 | 建议补 |
| P2 | 锦上添花，扩展视角 | 可选补 |
| P3 | 一般提醒 | 视情况 |

## 报告结构
```markdown
# <主题> 笔记缺口评审报告

## 评审配置
- 主题 / 受众 / 使用角色 / 评审日期

## 覆盖概览（主题-结构地图）
| 模块 | 深浅档位(提到/了解/会用/踩过坑) | 备注 |

## 缺口清单（按优先级排序）
| 优先级 | 层级(L1~L4) | 缺口 | 为什么缺(影响) | 补什么 | 怎么补(来源/方向) |

## 各角色专项意见
### <角色名>
- <该角色视角发现的核心缺口/坑>

## TOP 5 行动项
1. <最高优先级且最值得先补的一条，含一句话理由>
```

## 要点
- 每条缺口四要素齐全：缺口 → 为什么缺 → 补什么 → 怎么补。
- 深浅档位按"笔记实际呈现"标，不按主题应有深度标。
- 来源无法确认的补全方向标注"待核实"，不编造参考。
- 缺口要有证据（笔记里没有但该场景会被问/会出错），不写主观喜恶。
- 角色数一般 2~4，避免冗余；报告里体现每个角色的差异化价值。
