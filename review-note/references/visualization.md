# 评审总览图（Review Overview Visualization）

评审报告默认附带一张"评审总览图"，把覆盖地图与缺口优先级压成一张可一眼读完的静态图。用户明确只要文字/表格时不出图。

## 何时出图
- 缺口清单 ≥ 3 项，或覆盖模块 ≥ 5 个，且无用户"只要文字"的明确要求 → 出图。
- 只画"覆盖深浅 + 缺口优先级"两层核心信息；命令详解、易错点细节留在 markdown 表格，不塞进图。

## 输出格式
- 独立 HTML renderer 块：起始行逐字为 ` ```html type="renderer" `，结束行 ` ``` `，均独占一行。
- 静态优先，无外部脚本/依赖；文档级 `<title>` 非空（如"<主题>笔记评审总览"）。
- 桌面与窄屏均不重叠、不裁切；配色与文字颜色对比清晰。

## 三段构成（顺序固定）
1. **主题覆盖地图**：每个 in-scope 模块一张卡片，左侧色条 = 深浅档位
   - 提到 `#9aa4b2`（灰） / 了解 `#7aa2e3`（蓝） / 会用 `#2f9e63`（绿） / 踩过坑 `#1d7a55`（深绿）
   - 同档位模块可合并为一张卡，注明档位色；底部加一行档位图例。
2. **缺口优先级**：按 P1/P2/P3 分组
   - P1 `#e5484d`（红） / P2 `#f0a13a`（橙） / P3 `#7aa2e3`（蓝）
   - 每条 = 一句话缺口主题 + 归属角色（如"· 后端"）；P2/P3 可合并为一行多条。
3. **TOP 行动项**：前 1~2 项单独高亮卡片，其余合并为一行。

## 数据一致性（硬约束）
- 覆盖地图的模块与档位 = 报告"主题-结构地图"表格；缺口分组与数量 = 缺口清单，逐条对应。
- 图内不得出现表格中没有的新缺口、新档位或新数字；优先级数量角标（如"P1×4"）与清单实数一致。
- 底部注释示例："档位为评审结论；事实核验结果见报告"（不在图内放来源 URL，来源留在表格"怎么补"列）。
